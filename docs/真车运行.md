# ROSMASTER X3 真车运行 ORB-SLAM3

更新日期：2026-11-12。

当前环境：Jetson Orin NX、Ubuntu 22.04、ROS 2 Humble、Astra 相机。工程位于 `/home/jetson/ORBSLAM3`，本文以小车地址 `jetson@192.168.1.11`、ROS 通信域 `28` 为例。

## 1. 启动小车和 SLAM

在电脑上打开 A、B、C、D 四个终端，每个终端都执行：

```bash
ssh jetson@192.168.1.11
```

IP 不同时替换为小车的实际地址。四个终端的用途和启动顺序如下：

| 顺序 | 终端 | 用途           |
| ---- | ---- | -------------- |
| 1    | A    | 启动底盘       |
| 2    | B    | 启动键盘控制   |
| 3    | C    | 启动相机       |
| 4    | D    | 启动 ORB-SLAM3 |

在四个终端中分别执行以下设置：

```bash
export ROS_DOMAIN_ID=28
export ROS_HOME=/home/jetson/ORBSLAM3/runtime/ros
export ROS_LOG_DIR=/home/jetson/ORBSLAM3/runtime/ros/log
```

四个终端的 `ROS_DOMAIN_ID` 必须一致。以上设置只对当前终端及其启动的程序生效。

### 1.1 终端 A：启动底盘

```bash
ros2 launch yahboomcar_nav laser_bringup_launch.py
```

保持终端 A 运行。

### 1.2 终端 B：启动键盘控制

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```

点击终端 B，使它获得键盘焦点，并使用英文输入法。先按 `k` 保持停车，等 SLAM 就绪后再移动。

| 按键                  | 作用                         |
| --------------------- | ---------------------------- |
| `i` / `,`（英文逗号） | 前进 / 后退                  |
| `j` / `l`（小写 L）   | 原地左转 / 原地右转          |
| `k`                   | 停车                         |
| `z`                   | 线速度和角速度同时降低 10%   |
| `Ctrl+C`              | 退出键盘控制，退出前先按 `k` |

松开移动键不代表停车，停止时要主动按 `k`。首次测试可先按几次 `z` 降低速度。

### 1.3 终端 C：启动相机

先查询相机是否已经运行：

```bash
ros2 node list
```

没有相机节点时执行：

```bash
ros2 launch astra_camera astro_pro_plus.launch.xml \
  depth_registration:=true \
  color_depth_synchronization:=true
```

看到 `device started` 后保持终端 C 运行。启动文件的实际拼写是 `astro_pro_plus.launch.xml`。

### 1.4 终端 D：启动 SLAM

确认底盘、键盘控制和相机都在运行，并让小车保持静止，然后执行：

```bash
bash /home/jetson/ORBSLAM3/scripts/start_real_slam.sh
```

SLAM 只接收 RGB-D 数据，不会控制小车运动。每次启动会在 `/home/jetson/ORBSLAM3/results/real/` 中建立顺序编号目录，例如第 1 次为 `1`，之后为 `2`、`3`，不会覆盖旧结果。记住终端开头显示的 `SLAM output` 路径。

等待出现：

```text
X3_RGBD_READY: online TrackRGBD active
RUNNING ... processed=... tracked=... state=2
```

`X3_RGBD_READY` 表示算法已经初始化。`processed`、`tracked` 持续增加且大部分时间 `state=2`，表示图像正在处理并且跟踪正常。



# 显示特征点和地图窗口

需要查看特征点和稀疏地图，应先结束当前 SLAM，然后在电脑本地终端使用图形转发重新连接：

```bash
ssh -Y jetson@192.168.1.11
```

在新的终端 D 中重新设置第 1 节的三个环境变量，再执行：

```bash
QT_X11_NO_MITSHM=1 \
bash /home/jetson/ORBSLAM3/scripts/start_real_slam.sh -p viewer:=true
```

电脑将显示 `ORB-SLAM3: Current Frame` 和 `ORB-SLAM3: Map Viewer`。带窗口和无窗口方式不能同时启动，退出和保存仍按第 3 节操作。

## 2. 移动测试

1. 等 SLAM 就绪后，切换到终端 B。
2. 让相机朝向有清晰纹理和物体细节的场景。
3. 按 `i` 低速前进一小段，再按 `k` 停车。
4. 短暂按 `j` 或 `l` 缓慢转向，再按 `k` 停车。
5. 观察终端 D 中的 `tracked` 是否持续增加，`state` 是否大部分时间为 `2`。

首轮运行 30～60 秒即可。如果状态持续异常，先按 `k` 停车并保留终端 D 的输出。

## 3. 停车、保存和退出

按照以下顺序结束：

1. 在终端 B 按 `k`，确认小车停止。
2. 在终端 D 按一次 `Ctrl+C`，保持终端打开，等待保存和自动评估结束。
3. 看到 `X3_RGBD_SAVED` 后继续等待评估报告和 `X3_RGBD_EVALUATED: status=...`。
4. 终端 D 返回提示符后，在终端 B 按 `Ctrl+C` 退出键盘控制。
5. 在终端 C、A 分别按 `Ctrl+C`，停止本次启动的相机和底盘程序。
6. 各终端返回提示符后执行 `exit`，退出 SSH。

不要用直接关闭终端或断电代替上述保存步骤。`X3_RGBD_SAVED` 表示轨迹和统计已经保存；`X3_RGBD_EVALUATED` 表示自动评估已经结束。

| 评估状态   | 含义                     |
| ---------- | ------------------------ |
| `status=0` | 基础检查通过             |
| `status=1` | 报告中存在需要检查的问题 |
| `status=2` | 评估未能完成             |

基础检查通过只说明运行记录完整，不代表轨迹精度通过。

## 4. 查看和复制结果

每轮结果保存在启动时显示的编号目录中，例如：

```text
/home/jetson/ORBSLAM3/results/real/1/
├── camera.yaml
├── input_timestamps.csv
├── summary.txt
├── frames.csv
├── CameraTrajectory.txt
├── CameraTrajectory.txt.maps.csv  # 成功生成时存在
├── KeyFrameTrajectory.txt
└── evaluation.txt
```

查看自动评估报告时，将下面的 `1` 换成本轮编号：

```bash
cat /home/jetson/ORBSLAM3/results/real/1/evaluation.txt
```

报告主要检查：

- 是否正常保存，`failed` 是否为 `0`；
- 处理帧数、跟踪比例和最长连续异常状态；
- RGB-D 时间戳差、记录频率和最大图像时间间隔；
- 相机轨迹、关键帧和分地图轨迹是否生成；
- 轨迹的估计跨度、累计长度和起终点差。

需要把整轮结果复制到电脑时，在电脑本地终端执行：

```bash
mkdir -p collected_results
scp -r jetson@192.168.1.11:/home/jetson/ORBSLAM3/results/real/1 \
  ./collected_results/
```

将 IP 和结果编号替换为实际值。如果本地已经有同名目录，应改用新的接收目录，避免混合两轮结果。

## 5. 评估范围

当前报告用于判断真机输入、跟踪、保存和轨迹记录是否正常，不是完整的定位精度评估。

当前没有独立的参考真值，因此不能计算可信的 ATE/APE、RPE 及其 RMSE。轨迹长度和起终点差来自算法自身估计，也不能当作真实误差。若需要论文中的精度指标，还需提供与相机时间同步、坐标关系明确的参考轨迹。

本流程也没有记录原始 RGB-D 图像、每帧计算耗时或完整 Atlas 地图，尚未验收回环精度、地图几何精度和地图保存/加载功能。
